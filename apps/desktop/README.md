# Daksha for Windows and macOS

The full Daksha web app in a native desktop window (Electron). Every feature of the web app is here, including every connected app (YouTube,
Shopify, Home Assistant, …), their Manage popups, the assistant, calendar, email, tasks and notifications, because it **is** the web app, and new
apps appear automatically when the web app gets them.

What the desktop app adds:

- A native window that remembers its size and place, a native menu with shortcuts (`Ctrl/Cmd+1…9` jump to Dashboard, Assistant, Apps, Calendar, …).
- One window at a time per person; opening Daksha again focuses it.
- `daksha://apps/youtube` style links open that page in the app (Windows and macOS register the link type on install).
- Sign-in popups for connected apps work in-app (they report back and close themselves). Other links open in your browser.
- An offline page with a **Try again** button, and automatic retry when the connection returns.
- Safe by default: no Node access for the page, the page sees only `window.dakshaDesktop = { isDesktop, platform, arch }`, camera/microphone/location are refused,
  and only notifications and clipboard writes are allowed.

## Run it

```bash
cd apps/desktop
npm install
DAKSHA_APP_URL=http://localhost:3000 npm start      # your local web app (cd apps/web && npm run dev)
npm test                                            # 21 unit tests
xvfb-run -a npm run smoke                           # Linux: launches the real app and checks it (on Windows/macOS: npm run smoke)
```

## Which Daksha does it open?

In this order: the `DAKSHA_APP_URL` environment variable, `config.json` in the app's data folder (`{ "appUrl": "https://…" }`), then the address built into
the release (`src/app-config.json`, default `https://qa.daksha.ampalab.com`). `https://` is required except for `localhost`.

## Build the installers

Installers for a system must be built on that system. The easy way is GitHub Actions: **Actions → Desktop installers → Run workflow** (or push a tag such as
`desktop-v1.0.0`). It builds `Daksha Setup.exe` (Windows x64 and arm64) and `Daksha.dmg` / `.zip` (macOS Intel and Apple silicon) and attaches them to the run.
Set the repository variable `DAKSHA_APP_URL` (or the workflow input) so the installers open your Daksha.

By hand on the matching system:

```bash
DAKSHA_DEFAULT_APP_URL=https://app.example.com npm run dist:win    # on Windows
DAKSHA_DEFAULT_APP_URL=https://app.example.com npm run dist:mac    # on a Mac
```

### Signing (optional but recommended)

Without signing, Windows SmartScreen and macOS Gatekeeper warn on first launch. To sign, add these repository secrets: `CSC_LINK` (a base64 `.pfx`/`.p12`
certificate) and `CSC_KEY_PASSWORD`. For notarising on macOS also add `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` and `APPLE_TEAM_ID`. See Amit.md.

The icon is generated by `npm run icon` (`build/icon.png`); replace it with your own 1024×1024 PNG any time.
